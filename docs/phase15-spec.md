## M7. ورود Search Console

### 1. ورودی

خروجی گزارش Performance سرچ کنسول (Export ← Download CSV) که یک فایل zip است شامل `Queries.csv`، `Pages.csv`، `Dates.csv`، `Filters.csv`، `Countries.csv`، `Devices.csv` و `Search appearance.csv`. پایدارپرس این‌ها را می‌پذیرد:

- خود فایل zip (روش پیشنهادی؛ کاربر نیازی به باز کردن آن ندارد)
- یا یک یا چند فایل CSV جداگانه (`Pages.csv` و/یا `Queries.csv`)

فقط `Pages.csv`، `Queries.csv`، `Dates.csv` و `Filters.csv` خوانده می‌شوند؛ بقیه نادیده گرفته می‌شوند.

**تشخیص ستون‌ها** مستقل از زبان رابط سرچ کنسول است:

| ستون | انگلیسی | فارسی (هر کدام از این ریشه‌ها) |
|---|---|---|
| کلید | Top pages / Top queries / Date | صفحه / پرسش / عبارت / تاریخ |
| کلیک | Clicks | کلیک |
| نمایش | Impressions | نمایش / ایمپرشن |
| CTR | CTR | CTR / نرخ کلیک |
| جایگاه | Position | جایگاه / موقعیت / رتبه |

- ستون اول همیشه کلید است.
- **حالت مقایسه:** اگر برای یک معیار دو ستون وجود داشته باشد (مثلاً `Last 3 months Clicks` و `Previous 3 months Clicks`)، اولی دوره فعلی و دومی دوره قبل است.
- اعداد با ارقام فارسی/عربی، جداکننده هزارگان (`,` `٬`)، ممیز (`.` `٫`) و درصد (`%` `٪`) پشتیبانی می‌شوند. CTR به‌صورت کسر (0 تا 1) ذخیره می‌شود.
- جداکننده CSV (`,` `;` `Tab`) و BOM خودکار تشخیص داده می‌شود.
- بازه زمانی از کمینه و بیشینه `Dates.csv` به دست می‌آید؛ در نبود آن، از متن `Filters.csv` (مثلاً «Last 3 months») به‌صورت توضیحی ذخیره می‌شود.
- اگر فیلتر «Page» یا «Query» در `Filters.csv` اعمال شده باشد، هشدار داده می‌شود (داده ناقص است).

### 2. محدودیت‌ها و امنیت

- فقط کاربر با `paydarpress_manage`؛ درخواست REST با Nonce.
- حجم فایل حداکثر 10 مگابایت؛ حجم بازشده هر فایل داخل zip حداکثر 20 مگابایت (جلوگیری از Zip Bomb)؛ حداکثر 50٬000 ردیف در هر فایل.
- محتوای zip روی دیسک استخراج نمی‌شود؛ فایل‌ها در حافظه خوانده می‌شوند (`ZipArchive`، در نبود آن `PclZip` خود وردپرس).
- فایل آپلودشده ذخیره نمی‌شود؛ فقط ارقام و آدرس‌ها/عبارت‌ها.
- آدرس‌هایی که دامنه‌شان با سایت یکی نیست ذخیره نمی‌شوند (فقط شمارش می‌شوند).
- هر ورود در گزارش فعالیت ثبت می‌شود.

### 3. داده

جدول `{prefix}paydarpress_imports` (سابقه ورودها، برای M8 هم استفاده می‌شود):

| ستون | نوع |
|---|---|
| id | PK |
| type | `gsc` / `contentmaster` |
| file_name | نام فایل |
| status | `completed` / `failed` |
| summary | JSON (بازه، تعداد ردیف، تطبیق‌شده، هشدارها) |
| user_id | |
| created_at | |

جدول `{prefix}paydarpress_gsc` (فقط آخرین مجموعه داده؛ ورود جدید داده قبلی را جایگزین می‌کند):

| ستون | توضیح |
|---|---|
| id | PK |
| import_id | |
| kind | `page` / `query` |
| item | آدرس (رمزگشایی‌شده) یا عبارت جست‌وجو |
| item_hash | md5 برای Index |
| object_id | محتوای تطبیق‌داده‌شده یا NULL |
| clicks, impressions | عدد صحیح |
| ctr, position | اعشاری |
| prev_clicks, prev_impressions, prev_position | NULL در حالت بدون مقایسه |

نسخه Schema: 1.2.0.

### 4. تطبیق آدرس با محتوا

آدرس سرچ کنسول با همان `UrlNormalizer` اسکنر نرمال می‌شود. علاوه بر آن: حذف `#…` (پرش به بخش صفحه)، یکسان‌سازی `http/https` و `www`. اگر چند ردیف به یک محتوا برسند (مثلاً با و بدون `/` انتهایی)، کلیک و نمایش جمع و جایگاه میانگین وزنی (با نمایش) می‌شود. آدرس‌های تطبیق‌نخورده (برگه آرشیو، آدرس قدیمی، صفحه حذف‌شده) جداگانه نمایش داده می‌شوند؛ آدرس قدیمی با کلیک یعنی «ریدایرکت لازم است».

### 5. یافته‌های جدید ممیزی (گروه «عملکرد در گوگل»)

| کد | شدت | شرط |
|---|---|---|
| `GSC_NEAR_PAGE_ONE` | medium | جایگاه میانگین 8 تا 20 و نمایش ≥ `gsc_min_impressions` (پیش‌فرض 100) |
| `GSC_LOW_CTR` | low | جایگاه ≤ 5، نمایش ≥ 2 × `gsc_min_impressions`، CTR کمتر از 2٪ |
| `GSC_CLICK_DROP` | high | حالت مقایسه، کلیک دوره قبل ≥ 20 و افت ≥ 30٪ |
| `GSC_NOT_IN_SEARCH` | low | نوشته منتشرشده با بیش از 90 روز عمر، بدون noindex، که در `Pages.csv` نیست؛ فقط اگر بازه داده ≥ 28 روز و تعداد ردیف‌ها کمتر از 1٬000 باشد (سقف خروجی سرچ کنسول) |
| `GSC_DATA_STALE` | low (site) | آخرین ورود بیش از 60 روز پیش |

بدون داده سرچ کنسول هیچ‌کدام از این قواعد اجرا نمی‌شوند.

### 6. امتیاز بازنویسی

وزن‌های جدید: `GSC_CLICK_DROP` +25، `GSC_NEAR_PAGE_ONE` +20، `GSC_LOW_CTR` +10. اقدام: نوشته‌ای با `GSC_NEAR_PAGE_ONE` یا `GSC_LOW_CTR` حداقل «بروزرسانی سبک» می‌گیرد. در فهرست پیشنهاد بازنویسی، کلیک، نمایش و جایگاه نمایش داده می‌شود و دلایل جدید به زبان ساده اضافه می‌شوند.

### 7. خروجی JSON

- هر نوشته/برگه/محصول: `search_console: { clicks, impressions, ctr, position, prev_clicks }` (در خروجی فشرده: `gsc: [clicks, impressions, position]`)
- بخش جدید سطح بالا `search_console`: `period`، `imported_at`، `totals`، `top_queries` (حداکثر 200 عبارت پرنمایش با کلیک، نمایش و جایگاه)، `unmatched_pages` (حداکثر 50 آدرس پرکلیک بدون محتوا)
- `data_coverage.search_console`: `csv_import` یا `not_connected`

ContentMaster v1.5: در «بروزرسانی» از این داده استفاده می‌کند و در «موضوع جدید» عبارت‌های پرنمایش بدون مقاله اختصاصی را پیشنهاد می‌دهد.

### 8. رابط کاربری

صفحه «سرچ کنسول» در گروه «ورود و خروجی»:

- راهنمای ۴ قدمی گرفتن خروجی از سرچ کنسول
- آپلود (کشیدن و رها کردن zip یا CSV)
- خلاصه آخرین ورود: بازه، تعداد صفحه و عبارت، درصد تطبیق، هشدارها
- تب‌ها: فرصت صفحه اول، CTR پایین، افت کلیک، آدرس‌های بدون محتوا، عبارت‌های جست‌وجو
- حذف داده سرچ کنسول

پیشخوان: کارت «سرچ کنسول» (کلیک و نمایش کل، تعداد فرصت‌ها، تاریخ داده). فهرست محتوا: ستون‌های کلیک/نمایش/جایگاه در حالت حرفه‌ای.

### 9. معیار پذیرش M7

1. zip واقعی سرچ کنسول (انگلیسی و فارسی، با و بدون مقایسه) بدون ویرایش وارد شود.
2. ≥ 95٪ آدرس‌های نوشته‌های موجود تطبیق داده شوند.
3. یافته‌ها و امتیاز بازنویسی بلافاصله پس از ورود بروز شوند.
4. فایل مخرب (zip bomb، CSV بسیار بزرگ، HTML در خانه‌ها) بدون خطا رد یا پاک‌سازی شود.
5. حذف داده سرچ کنسول همه یافته‌های گروه را برطرف‌شده علامت بزند.

## M8. ورود از ContentMaster (خلاصه؛ جزئیات پیش از شروع M8)

- ContentMaster یک فرمان «خروجی پایدارپرس» می‌گیرد که JSON با `schema: paydarpress-import/1` تولید می‌کند: `topics[]`، `articles[]` (عنوان، اسلاگ، HTML، دسته، برچسب، کلمه کلیدی، متا، Alt، FAQ)، `link_suggestions[]`.
- موضوعات در صندوق «موضوعات پیشنهادی» (جدول `topics`) با وضعیت جدید/پذیرفته/ردشده.
- مقالات فقط به‌صورت **پیش‌نویس**، HTML با `wp_kses_post`، فقط فیلدهای سئوی افزونه فعال (Yoast/Rank Math/AIOSEO).
- پیش از ایجاد: پیش‌نمایش و هشدار تکرار (عنوان/کلمه کلیدی مشابه موجود).

## M9. صف تأیید لینک داخلی (خلاصه)

- منابع: پیشنهادهای ContentMaster و پیشنهادهای خود افزونه برای محتوای یتیم.
- هر پیشنهاد: نوشته مبدأ، متن لنگر موجود در متن، مقصد؛ پیش‌نمایش جمله.
- درج فقط پس از تأیید مدیر، روی اولین رخداد متن لنگر خارج از لینک/عنوان موجود، با ذخیره Revision وردپرس؛ برای المنتور فقط پیشنهاد (بدون درج خودکار).
